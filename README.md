# TO_printing — トポロジー最適化つき 3Dプリント設計

水中ドローン等の新しい部品には、[荷重・初期モデル・サポートの手順](docs/underwater-design.md)と
[ブラケットの入力例](examples/underwater_bracket/README.md)を用意しています。

> 3Dプリント部品を「たぶん丈夫」ではなく**数値で確かめてから**印刷するためのツールと、その実例。

既存の部品に取り合う部品を設計するとき、いちばん危ないのは「見た目は良いが、どこが効いているのか
誰も知らない形」ができることです。このリポジトリには、荷重を N で決め、有限要素法（FEA）でたわみと
安全率を測り、トポロジー最適化で材料の置き場所を探し、そのまま Bambu Lab X1 Carbon で
印刷できるかまで判定する、一連の手順が入っています。

**ツール本体**（`topopt/`）と、それを使って実際に作った**実例**（`osmo_tripod/` — DJI Osmo Action 6 用の
三脚ホルダー）で構成されています。ツールは一度入れればどのプロジェクトからでも使えます。

## これで何ができるか

- **剛性・強度を測る** — STL を渡すとボクセル FEA を回し、たわみ・von Mises 応力・
  積層方向を考慮した破壊指標・安全率を出す
- **形を探す** — 「ここは残す／ここには置けない／ここは自由」を指定すると、
  最適化が荷重を支える形を探す（Fusion Generative Design と同じ考え方）
- **印刷できるか判定する** — プリンタに載るか、どの向きが良いか、サポートが実際に何 mm² 付くか、
  細すぎる部分がないか
- **実寸を読む** — 相手部品の STEP から断面図と正確な寸法を取り出す。可動部の掃引干渉も見る

必要なのは Python と numpy / scipy だけです。CAD ソフトも商用ソルバも要りません。
単位はすべて mm / N / MPa で統一されています。

## どう動いているのか

中身は一言でいうと「**部品を細かい立方体の集まりに置き換えて、その一個ずつを計算する**」ツールです。
CAD の曲面をそのまま扱う代わりに、形をレゴブロックのように分解してしまうので、
CAD カーネルが要らず、同じ仕組みで FEA も最適化もできます。

1. **形を格子にする** — STL を読み、部品の中身を一辺 1 mm 前後の立方体（ボクセル）で埋める。
2. **一個ずつを弾性体として解く** — 立方体それぞれをバネの塊とみなし、
   荷重をかけたときの全体のつり合いを反復計算で解く。出てくるのがたわみと応力。
3. **材料を置く場所を探す（最適化）** — 立方体ごとに「材料の詰まり具合」を 0〜1 の数値で持たせ、
   柔らかくなる場所の材料を減らし、力が集中する場所へ回す。これを数十回繰り返す。
   このとき「絶対に残す領域（preserve）」「絶対に置かない領域（obstacle）」は固定したままにする。
4. **形に戻す** — 詰まり具合が 0.5 を超えた立方体を集めて STL / STEP として書き出す。
5. **印刷できるか調べる** — 向きを変えながらサポートが付く面積・最小の肉厚・プリンタに載るかを測る。

この作り方には割り切りがあります。**立方体の大きさより細かい寸法は表現できません**。
そのため最適化の出力は「材料をどこに置けばよいかの地図」として使い、
取合い部の寸法は CAD 側で作り直す前提になっています（`compare` がその確認用です）。

**ただし取合いだけは、CAD のまま出せます。** 相手と噛み合う部分は「絶対に残す領域」なので、
最適化は一度も触っていません。だから出荷する形を作るとき（`finish` 段）は、そこだけ
**CAD の図形をそのまま入れ直します**——立方体より細い爪や溝でも消えません。
2026-09-09 からは、その CAD の**面の位置**も立方体の境界に丸められません
（各立方体を CAD がどれだけ埋めているかを見ています）。それ以外の部分は上の割り切りのままです。

## 現在の状態

ツールは動いています（自己診断つき）。いま進めているのは次の2点で、
仕様は [docs/spec.md](docs/spec.md) にあります。

1. **積層方向による硬さの違い（直交異方性）を最適化に入れる** — 済（2026-08-05）。
   3Dプリントした部品は、積層の向きによって硬さも強さも変わります。とくに**層と層のあいだは弱い**。
   最適化がその差を知らないと、「立てて印刷すると割れる形」を最適解として出してきます。
   いまは印刷の向き（`build_axis`）が材料の置き場所そのものに効くようになりました。
   同じ部品・同じ荷重でも、寝かせて印刷するか立てて印刷するかで**安全率が 2 倍以上変わります**。
   ただし**材料の数値は文献からの暫定値で、実測ではありません**（→ 下の「限界」）。
2. **CalculiX による独立した再解析** — **実行検証済**（2026-09-08）。
   最適化と同じプログラムで検証しても、同じ思い込みは見つかりません。
   別のソルバ・別のメッシュで解いて同じ結論が出ることを検証とします。
   2026-09-08 に Gmsh と CalculiX をこの環境に実際に入れて `topopt ccx` を初めて回したところ、
   最初の実行で4件の不具合が見つかりました（要素セット名の不一致、ステップをまたぐ拘束・荷重の
   持ち越し、複数ケースの結果が最後のケースにまとめられてしまう、OpenSCAD が書く非閉曲面の
   STL でメッシュ生成が止まる）。いずれも直しました（詳細は
   [docs/known-issues.md](docs/known-issues.md) A2）。
   **そのうえで、既存のボクセル FEA と CalculiX を同じ部品で突き合わせたところ、
   6つの荷重ケースのうち4つで変位が 15% を超えて食い違いました**（22〜40%）。
   原因を追ったところ、**メッシュの切り方そのものにありました**——Gmsh は渡した STL の
   三角形をそのまま表面メッシュにするので、「メッシュを細かくする」収束スタディを回しても
   境界の解像度は一度も変わっておらず、ある脚の支持面はわずか STL 頂点9個しか掴んでいませんでした。
   渡す前に表面を分割し、境界条件の節点の拾い方をボクセル経路と揃えたところ、
   **6ケースとも変位が 15% 以内（最悪でも 5.4%）まで一致しました。**
   **ただし、これは「収束した」という意味ではありません。** 同じ部品でメッシュ収束
   （4/2/1 mm）を回すと、**まだどの段階も収束していません**（応力の値が段階ごとに
   13〜32% 動きます）。**一致したことと、収束したことは別です**——今回一致した数字も、
   まだ動いている途中の値として扱ってください
   （[docs/known-issues.md](docs/known-issues.md) A6）。
3. **ソルバの高速化** — 済（2026-09-05）。遅かったのは物理ではなく、
   連立方程式 `K u = f` の**解き方**でした。ボクセルを粗い格子へ段階的にまとめて解く
   前処理（幾何マルチグリッド）に替えたところ、必要な反復回数が数千から数十に減りました。
   GPU（torch が CUDA を見つけた場合）があれば、さらに1反復あたりの計算がおよそ30倍安くなります。
   実測では、実物部品 child_core_frame の解析が 59.7 分 → 22 秒、
   検証用 tall_tripod（4 mm 格子、約 10 万要素）の1ケースあたりの解き時間が約 540 秒（旧ソルバ換算）→ 2.2 秒になりました。
   4 mm 格子・6 荷重ケース・80 反復の tall_tripod 一括 run（`topopt run`）は、従来の見積もり十数時間に対し
   **6.6 分**（最適化 342 秒、480 解）で完走しました。
   **結果（たわみ・応力・安全率）は変わっていません**（4桁一致）。
   ただし**GPU が無い環境ではここまでの短縮にはならず**、CPU だけでもおよそ20倍にとどまります。
   **続報（2026-09-08）：同じ答えのまま、さらに 2.5 倍。** 遅さの原因は 4 つあって、どれも物理では
   ありませんでした。(1) GPU に渡す `0.0` のような定数を毎回コピーしていて、そのたびに GPU が
   仕事を止めて待っていた、(2) 「材料を置けない場所（obstacle）」が密度 0 の要素として毎回解かれて
   いた（子機ジョーゲートでは域の 49 %）、(3) 体積を合わせる探索が毎反復ゼロから始まっていた、
   (4) GPU の倍精度の行列積が 1 回の計算の 2/3 を占めていた（前処理だけ単精度にし、答えを決める
   外側の反復は倍精度のまま）。子機ジョーゲート（3 mm・約 10 万要素・5 荷重ケース）の
   最適化 4 反復で 24.6 秒 → 9.9 秒、連立方程式 1 反復あたり 19.6 ms → 6.6 ms。答えは
   コンプライアンス相対差 1e-6 以内で同じです。
   **試行を重ねる段階は `topopt run ... --quick`** で、CalculiX・スライサー・平滑 STL・STEP・
   finish 形状を飛ばして、設定検査・最適化・最終 FEA・造形性検査だけを回せます
   （反復数は変えません。減らすと別の最適化になるので、短くするなら `--iters` で明示します）。
   **限界**：材料がほとんど無い study（volfrac 0.05 程度）は、最適化の途中で構造が切れかけて
   連立方程式の反復が 1 回の解につき 1,000 回に達します。それは study の性質で、
   ソルバの速さでは埋まりません（`cg_iterations` を見れば分かります）。
4. **印刷できる形を出す** — 済（2026-09-05）。最適化が積層方向（`build_axis`）を知るようになりました。
   立方体は、その真下の45°の円錐（直下＋面内4近傍）に材料があるときしか材料を持てません
   ——プレート（設計空間の最下層）から積み上げるように、層ごとに判定します。
   しきい値処理で出た形は、さらに「印刷できる部分集合」だけに絞り込みます。
   結果：最適化された材料の非支持ボクセルが 460 個 → **0**、平滑 STL の要サポート面積が
   4.7 % → **3.0 %**（残りはマウント頭部の下面で、そこは CAD で面取りする仕事です）、
   部品は 6 個のパッドで接地し、浮き島（材料の孤立した塊）はありません。
   **限界**：ブリッジ（短い水平スパン）は知らないので保守的に非支持扱いになります。45°しか選べません。
   マウント頭部の下面は CAD で面取りしてください。
   旧挙動（積層方向を考えない最適化）に戻したいときは study の `design` に `"overhang": false` を書きます。
   **サポートが必要なときは条件つきで許せます**：`"overhang": {"max_support_mm": 20}` で
   高さ 20 mm 以下のサポート柱なら許す、`{"allow_support": ["領域名"]}` でその領域だけ許す。
   何を許したかはレポートに残ります。

検証には2つのモデルを使います。

- **`osmo_tripod/`（実物・低重心）** — 一通り完走している既存の部品。
  変更で結果が変わっていないかを見る**基準**として残します。
- **`osmo_tripod/tall_tripod.scad`（検証用・背が高い）** — カメラを 15 cm 上げたモデル。
  低重心のほうは材料を置ける空間がほぼ平板で、最適化に考えさせる余地が薄いためです。
  詳しくは [tall_tripod/README.md](tall_tripod/README.md)。

## セットアップ

Python 3.10 以上が必要です。

```bash
pip install -e "topopt[all]"     # numpy/scipy + matplotlib + scikit-image
python -m topopt --help          # コマンド一覧
python topopt/tests/smoke.py     # 自己診断（数秒）
```

自己診断が全項目 PASS すれば導入できています。
`[all]` を付けない最小構成でも動きますが、PNG 出力と平滑 STL が使えません。

GPU は任意です。torch（CUDA ビルド）を入れておけば自動的に使われ、解析が速くなります。
入れなくても numpy / scipy だけで動きます。`--solver cpu` を付ければ、GPU があっても CPU 経路を強制できます。

インストールせずに試すこともできます。

```bash
PYTHONPATH=topopt/src python -m topopt --help
```

CalculiX（構造解析）と Gmsh（メッシュ生成）を入れると、`topopt ccx` で
独立した再解析ができるようになります。どちらも必須ではありません——入れなくても、
これまで説明した FEA・最適化・造形性判定はそのまま動きます。

1. Gmsh は [gmsh.info](https://gmsh.info/) の zip 版、CalculiX は
   [dhondt.de](https://www.dhondt.de/) の Windows ビルド（`calculix_2.23_4win.zip`）を落とし、
   どちらも自分のユーザーフォルダの下（例：`Tools\`）に展開するだけです。
   インストーラは無く、管理者権限も要りません。
2. `topopt` は展開した場所を、環境変数 `TOPOPT_GMSH` / `TOPOPT_CCX` で教えるか、
   `%USERPROFILE%\Tools\` 以下を自動で探して見つけます。
3. `python -m topopt ccx --check` を実行すると、両方が見つかっているか確認できます。

`--repair` を付けると、OpenSCAD（特に 2021.01 系）が書き出す、面が閉じきっていない STL を
自動で修復してからメッシュを切ります（`pip install pymeshfix` が別途必要です）。

### スライサー（造形時間と材料量を知りたいとき・任意）

`topopt slice` は、できあがった STL を**実際のスライサーに通して**、
「何時間かかるか」「フィラメントを何グラム使うか」「そのうち何グラムが
サポート（あとで捨てる足場）か」を読み取ります。これらは形だけを見ても分からない量で、
**スライサーからしか出ません**。

このリポジトリでは **Bambu Studio**（`C:\Program Files\Bambu Studio`）を使います。
X1 Carbon 自身のスライサーなので、プリンタ・材料・積層高さの設定がそのまま使え、
出てくる造形時間は実機の表示と同じ数字です。OrcaSlicer が入っていればそちらでも動きます。

```bash
python -m topopt slice part.stl --out DIR
```

> FreeCAD は**まだ使っていません**。FreeCAD もスライサーも必須ではなく、
> 入っていない環境では該当コマンドだけが「未導入」と表示して止まります（終了コード 3）。
> **スライサーが無い・失敗したことが、部品の合否を動かすことはありません。**
> レポートには「測っていない（UNKNOWN）」と出ます。

## 使い方

`topopt <コマンド>` の形で使います。`topopt <コマンド> --help` で引数が出ます。

| コマンド | 何をするか |
|---|---|
| `assumptions` | 前提条件を1枚にまとめる（荷重・材料・機械・何が固定されていたか） |
| `setup` | 設計空間の設定を検証して 3D プレビューを出す（数秒。**解く前に**）。**印刷範囲に入るかもここで見る** |
| `opt` | トポロジー最適化を回す |
| `fea` | STL に対する FEA（たわみ・応力・安全率） |
| `compare` | 作り直した形は、まだ荷重を支えているか |
| `run` | setup → opt → extract → ccx → print → report → publish を一括 |
| `print` | プリンタに載るか・最適な向き・最小フィーチャ・どこで割るか |
| `overhang` | この向きで実際にサポートが要る面積 |
| `slice` | スライサーに通して実際の造形時間・材料量・サポート量を読む |
| `sections` | STL を切って実寸を読む |
| `clearance` | ヒンジまわりに相手を振って干渉を見る |
| `step2stl` | STEP → STL |

トポロジー最適化の典型的な流れ：

```bash
python -m topopt setup   study.json --out out/gd            # 数秒。設定ミスをここで潰す
                                                            # out/gd/*_setup.png を必ず見る
python -m topopt opt     study.json --out out/gd --iters 50 # 数分〜数時間
python -m topopt compare out/gd rebuild.stl --study study.json
```

**終了コードは「クラッシュしたか」ではなく「所見」です。** `setup` は 0=有効 / 1=無効 / 2=読めない、
`opt` は 0=繋がっていて全ケース安全率を満たす / 1=満たさない、を返します。

読む順番としては、まず [docs/workflow.md](docs/workflow.md)（荷重の決め方から印刷までの手順書）、
コマンドの詳細は [topopt/README.md](topopt/README.md)、
設計空間の書き方は [topopt/docs/design-space.md](topopt/docs/design-space.md) です。

### 覚えておくとよいこと

- **最適化の結果はそのままでは部品になりません。** 出てくるのは「材料をどこに置けば荷重を支えられるか」
  の地図で、取合い寸法は格子に丸められています。primitives で作り直して `compare` で確かめてください。
- **判定は p99.5 安全率で見ます。** 最悪要素の値は、拘束面の計算上の尖りであることがよくあります。
- **メッシュ収束を確認していない数値は使わないでください。**
- **材料の数値はまだ実測ではありません。** PLA / PETG の直交異方性カード（弾性 9 定数＋強度 9 個）は
  文献の傾向から保守側に置いた暫定値で、**このプリンタ・このフィラメントで測ったものは 1 つもありません**。
  そのため要求安全率は 3.0 ではなく **4.0** で報告します。
  **絶対値ではなく「どの向きに印刷すべきか」の比較に使ってください。**
- **「強度が足りているか」と「実物が組めるか」は別の話です。** osmo_tripod は
  強度・剛性・造形性の判定を全部通ったうえで、**相手の部品が入らずに作り直しになりました**。
  はめあいは「相手が入るか」を数字で書いて、それも検査してください
  （[docs/workflow.md](docs/workflow.md) の「はめあいは『相手が入るか』で assert する」）。
- **どのソルバで解いたかは、出力 JSON に必ず残ります。** `solver` と `cg_iterations` を見れば、
  GPU で解いた結果と CPU で解いた結果を区別できます。
- **`build_axis` は「解析した積層方向」であると同時に「印刷する向き」です。** あとからサポートを
  減らすために向きを変えないでください——向きを変えたら study を作り直して解き直します。
- **強度そのもので形を決めたいときは `design.stress` があります。** 既定では使いません
  （従来どおり、材料の量と剛性だけで形を決めます）。使うと、最適化が回っている最中に
  「必要な安全率を下回っていないか」を計算グリッドの上で見ながら形を探します。
  **ただしこれは最適化中の見積もりにすぎません。** 最終的な合否は、仕上がった形を
  もう一度解析した安全率（p99.5・最悪要素）で決まります。

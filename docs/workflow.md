# 設計手順ノート

> 既存部品に取り合う 3Dプリント部品を、荷重を数値で決めてから設計し、検証して印刷するまでの手順。
> コマンドの引数は [../topopt/README.md](../topopt/README.md)、設計空間モデルの全仕様は
> [../topopt/docs/design-space.md](../topopt/docs/design-space.md)、
> つまずいた記録は [lessons-learned.md](lessons-learned.md)。

---

水中ドローンなど別の部品から始める場合は、[荷重・初期モデル・サポートの手順](underwater-design.md)と
[実行可能なブラケット例](../examples/underwater_bracket/README.md)を使う。
一括実行の独立解析は完成STLを既定とする。同形状でのソルバ比較には`--ccx-geometry analysis`を指定する。

## 1. 取合い相手の実寸を取る（推定しない）

CAD カーネル（FreeCAD / CadQuery）が無い環境でも、STEP の**解析曲面エンティティ**を直接読めば
正確な値が取れる。円筒・円は `CYLINDRICAL_SURFACE` / `CIRCLE` に半径・中心・軸がそのまま書いてある。

```bash
python -m topopt step2stl part.step out.stl      # 形を見るため
python -m topopt sections out.stl sections.png   # 断面で寸法を読む
grep -E 'CYLINDRICAL_SURFACE|CIRCLE' part.step   # 穴・R は解析値で取る
```

> **`step2stl` は平面 BREP 専用で、円筒面を落とすので水密にならない。**
> 見る・測るには十分だが、レイキャストによる内外判定には使えない。
> 干渉判定は解析的条件かバウンディングボックスで行うこと（`topopt clearance` 参照）。

## 2. 荷重を数値で決める

「頑丈に」ではなく N で書く。人に聞く。決まるまで設計に入らない。
書き方の実例は `osmo_tripod/osmo_tripod.md` §2。

落下は**エネルギー法で評価できない**。剛体接触では剛性が支配的になりピーク荷重が発散するので、
等価減速度（g）で評価し「何 g で壊れるか」を答えにする。

## 3. モデリング前に閉形式で断面を決める

梁・ラグの手計算で当たりを付けてから形を描く。`3d-print-design` スキルの `quick_strength.py` は
`topopt/src/topopt/materials.py` から材料値を読むので、閉形式チェックと FEA が別の数字を使うことはない。

```bash
python <skill>/scripts/quick_strength.py beam --L 40 --b 19 --t 17 --F 31 --material PLA --sf 3
python <skill>/scripts/quick_strength.py lug  --hole 5.2 --edge 9.5 --t 2.5 --F 122 --material PLA --sf 3
```

## 4. パラメトリックに書く（assert つき）

- Customizer ブロックに全寸法を置き、以下は導出する。
- `cube` / `cylinder` / `polygon` + boolean のみ（`hull` / `minkowski` は面数が爆発する）。
- **フィーチャ同士のクリアランスを `assert()` する。** watertight は「意図した形」を保証しない。
- **assert が落ちたら形を直す。assert を緩めない。**

### はめあいは「相手が入るか」で assert する

自部品の中だけで矛盾が無いことを確かめる assert は、**相手が入らないことを検出できない**。
osmo_tripod は assert 20 個・watertight・サポート 0・FEA 合格で、実物に相手が入らなかった
（[lessons-learned.md](lessons-learned.md) 22〜26）。書くべきなのは相手との関係のほう。

- **すきまは「下限」として書く。** `assert(相手の隙間 - 自分の厚み >= 0.5)` の形。
  導出値どうしの一致確認（`abs(a - b) < 1e-9`）は誤記は防ぐが、はまるかは何も言わない。
- **同時に空いている面を数える。** 相手が一体物なら、接する面は**全部同時に**空いている必要がある。
  「溝 3.50 に爪 3.00 だから 0.50 空いている」ではなく「片面 0.25 が4か所」。
- **すきまのノブを1つにまとめない。** 広げると部材が痩せる側（上限あり）と、
  外へ動くだけの側（上限なし）は別の変数。1つにすると細い側に引きずられる。
- **「入る相手の寸法」を「穴の寸法」に代入しない。** Ø22 のノブに Ø22 のポケットは入らない。
- **FFF の誤差方向を見込む。** 内側形状（穴・溝）は縮み、外側形状（軸・爪）は太る。
  公称 0.25 mm/片面は、実物ではしばしば 0.1 mm 以下になる。
- **閾値ちょうどの面を作らない。** ちょうど 45.0° の面は造形性判定の厳密不等号を跨いで揺れる。

ヒンジまわりの干渉は解析的に閉じられる。回転軸まわりに回る相手は軸からの距離が回転で変わらないので、
「自部品の半径 < 相手の最近接距離」を満たせば全角度で干渉しない。assert 1行で書けて、数値検証より強い。

### 締結部は「入るか」だけでなく「入れられるか」を検査する（2026-09-09）

ナットは**外から押し込む**。ポケットの寸法が正しくても、**口が塞がっていれば入りません**。
tall_tripod v5 はナットポケットの寸法も逃がしの径も正しく、`obstacle` にも宣言してあり、
干渉掃引も通り、それでも組めませんでした——**台座（preserve）がポケットの口を覆っていた**から。

- **`obstacle` は最適化が置く材料を退けるだけで、`preserve` を退けない。**
  部品の外の逃がしは `obstacle` と `finish.cut` の**両方**に書く。
- **assert は「進入路が塞いでいるものの外まで届いているか」で書く。**
  `assert(fin_nut_x1 + tool_depth >= ped_bot_x + 1.0)` のように、
  「口の位置」ではなく「口から外へ抜けているか」を見る。
- **出荷 STL でも数える。** 口を横切るライン1本ずつについて、外向きに材料が残っていないかを
  数えるだけの検査で足ります（`tall_tripod/02_setup/check_interface.py`）。
  v5 の出荷 STL は 3,228 本中 758 本が閉じていました——**図では見えません**。
- **ネジが押す壁の厚みにも assert を置く。** 兄弟モデルに同じ assert があるなら写す。
  tall_tripod にはそれが無く、ナットポケットの床は 1.80 mm でした（osmo_tripod の下限は 2.50）。

## 5. 造形性を見る

```bash
python -m topopt overhang part.stl                        # 実サポート面積
python -m topopt print part.stl --printer X1C --load-axis 1,0,0
```

> `topopt print` の `overhang_pct` は**ベッド接地面そのものを含む**ので、平底の部品でも
> 「24% オーバーハング」と出る。切り分けは `topopt overhang`。

平底にすると三つ得をする（サポート 0、ベッド接地最大＝落下に強い、曲げ引張が層内に乗る）。
脚は「細い棒」ではなく「背の高い平底リブ」にする。
六角ナットざぐりは必ず 30° オーバーハングになるので、頂点を上げて 45° の尖り屋根にして自己支持させる。

### 5.1 スライサーの数字を読む（`topopt slice`）

ここまでの造形性チェックは全部**形しか見ていない**。「何時間かかるか」「フィラメントを
何グラム使うか」「そのうち何グラムを足場（サポート）として捨てるか」は、
**ノズルの通り道を計算しないと分からない**——つまりスライサーからしか出ない。

```bash
python -m topopt slice part.stl --out DIR                       # 既定：X1C / 0.20 mm / PLA / サポート auto
python -m topopt slice part.stl --out DIR --supports none       # サポート無しならどうなるか
python -m topopt slice part.stl --out DIR --supports tree       # 枝状サポート
```

出力は `DIR/slice.json` と、スライスした `DIR/<部品名>.3mf`（Bambu Studio でそのまま開ける）。
実測例（Bambu Studio 02.05.00.66・X1C・0.20mm Standard・Bambu PLA Basic・`--supports auto`）：

| 部品 | 造形時間 | フィラメント | うちサポート | 層数 |
|---|---|---|---|---|
| `osmo_tripod.stl`（平たい三脚） | 36分39秒 | 18.25 g | **0 g（0%）** | 162 |
| `tall_tripod_study_t40.stl`（背の高い三脚・**解析グリッドの本体**） | 4時間7分42秒 | 169.53 g | **48.58 g（28.7%）** | 1035 |
| `tall_tripod.stl` v8（**出荷する形**。取合いが別部品に差し替わり、解き直した版） | 6時間53分4秒 | 294.76 g | **130.51 g（44.3%）** | 1263 |

**2 行目と 1 行目は別の形です。** 2026-09-10 まで `topopt run` の `slice` 段は
`outputs["stl"]`——publish が `*_raw.stl` と名付けている**解析グリッドの本体**——を
スライスしていました。取合いが小さいうちは差も小さかったのですが、v7 で取合いが
143 cm³ の別部品になった瞬間、**114 g・49 分ぶん存在しない部品の見積もり**になりました。
いまは出荷する形（`finish_stl`）を測ります（lessons-learned #98）。

**読み方は5つ。**

- **サポート 28.7% は「設計の警告」である。** 材料の3割近くを、印刷して、外して、
  捨てるために使っている。形を変える（自己支持にする・向きを変える・分割する）
  価値がどれくらいあるかの見積もりが、ここで初めて数字になる。
- **`layers` と `object_layers` は違うことがある。** 標準プロファイルは
  サポートに独自の層高さを許すので、機械が実行する層数（`layers` 1035）が
  部品の層数（`object_layers` 700 ＝ 高さ140 mm ÷ 0.20 mm）を超える。
  時間に効くのは前者。
- **`support_mm3` は「押し出すフィラメントの体積」であって、
  `printcheck.json` の `support_volume_mm3`（部品空間でサポートが占める体積）ではない。**
  別の量なので並べて比較しない。前者は捨てる材料の量、後者は形の話。
- **spec §13.3 のサポート合格条件は、スライサーでは判定できない。**
  5条件はどれも「サポートが**どこに**付くか」を問うている（密閉空洞の中／工具が届かない場所／
  preserve の座面／外すときに細い部材を折る）のに対し、スライサーは
  「**どれだけ**付くか」しか言わない。だから `slice.json` は5条件を**理由つきで
  全部 UNKNOWN**として残す。位置の判定は `printcheck.json` を見る。
- **スライサーが無くても・失敗しても、部品の合否は動かない。** `topopt report` は
  スライサーを合否の停止条件に入れず、独立した節に出す。`slice.json` が無ければ
  「UNKNOWN（測っていない）」と明記する。造形時間と材料量は他のどこでも推定していないので、
  黙って空欄にすると「問題なし」と読まれてしまうため。

> **向きは既定で変えない（`--orient keep`）。** `--orient auto` を付けるとスライサーが
> 部品を寝かせて置くことがあり、そうすると**層の向きが変わる**。
> `build_axis` を前提にした直交異方性の解析は、その向きの物体を記述していない。
> 「別の向きなら入る／速い」を合格にしないのと同じ理由。

## 6. FEA

```bash
python -m topopt fea study.json --out DIR              # 粗く回して設計を直す
python -m topopt fea study.json --out DIR --voxel 0.67 # 最後に1回、収束させる
python -m topopt fea study.json --out DIR --converge   # [2H, H, H/2] の3段階でケースごとに収束を判定
```

- 判定は **p99.5 安全率**。最悪要素は拘束面のアーティファクトのことが多い。
- **メッシュ収束チェックが通っていない数値は使わない。** `--converge` はそれを自分では判断させず、
  変位5%・p99.5応力10%・ホットスポット位置（最細ボクセルの2倍以内）で機械的に判定する
  （`<base>_fea_convergence.json`）。osmo_tripod を4/2/1 mmで回すと**全ケースが未収束**
  （p99.5応力が13〜32%動く）——粗いメッシュの数値を「だいたい合っている」の根拠にしない。
- 固定領域を厚く取ると構造が短くなる（固定した節点はすべて梁を短くする）。境界条件は要素より先に疑う。

## 7. トポロジー最適化 — 設計空間を先に書く

Fusion Generative Design と同じ4種類のジオメトリで設定を書く。
**preserve**（密度 1・絶対に削られない）／ **obstacle**（密度 0・クリアランス付き）／
**design_space**（最適化変数）／ **optional_starting_shape**。
実例は `osmo_tripod/gd_mount_study.json`。

```bash
# まず設定を検証してプレビューを出す（数秒）。ここで間違いを潰す。
python -m topopt setup gd_study.json --out out/gd
# out/gd/*_setup.png（緑=preserve 赤=obstacle 灰=design space）と *_setup.scad を必ず見る

python -m topopt opt     gd_study.json --out out/gd --iters 50
python -m topopt compare out/gd rebuild.stl --study gd_study.json
```

> **形を探している間は `topopt run ... --quick` で回す（2026-09-08）。** 設計空間・obstacle・
> volfrac・フィルタ寸法を変えて何本も試す段階では、しきい値 1 つ・CalculiX と
> スライサーなしの探索プリセットで後段の時間を削る（反復数は変えない——減らすと継続
> スケジュールが圧縮され、跳ね上がりから戻れない study がある。lessons-learned #88）。合否を決める段（設定検査・最適化・最終 FEA・
> 造形性検査）はそのまま走るので、体積・安全率・たわみの比較には使える。
> 案が固まったら**保存密度から後段を `--quick` なしで実行する**——3 しきい値の比較・独立再解析・
> 実スライス・finish 形状はそちらでしか出ない。GPU は 1 本ずつ使う（3 本同時に回すと
> 18 分の見積もりが 7 時間になった実測がある）。
> 再利用はstudy・グリッド・最適化設定が同じ場合に限る。元のrun_summary/manifestを保存し、
> 必要な解像度・材料モデル・ソルバ設定を後段にも渡す。条件変更時は新しい出力先で再optする。

ソルバを回す前にエラーになる主なもの：

- **荷重・拘束は preserve の上にしか置けない。** 自由セルに荷重を置くと、最適化は
  「押している当の相手」を消してよいと解釈し、実際に消す。
  **例外は接地だけ。** `{"contact": "ground"}` と書いた support は preserve ではなく
  **設計空間の底面1ボクセル層**に切り詰められ、**接地面の節点だけ**を固定する。
  最適化が床に何も置かなければコンプライアンスが発散して自分に返るので、規則の目的は守られる。
  **足を CAD で描かずに済む唯一の手段**だが、**転倒は表現できない**（両側拘束のため）。
  片側支持のケースを1方位しか書かないと、倒れる形が安全率 128 で合格する。→ known-issues G7
- **preserve は一切侵食されない。** フィルタ・射影・対称化・しきい値処理・連結成分の掃除・
  スムージングは全部 preserve を書き戻す**前**に走る。
- **preserve 同士が設計空間経由で繋がらない設定はエラー。**
- **穴あき部品は「実体を preserve・穴を obstacle」で書く。** 穴あき STL を preserve に渡すだけだと、
  穴は自由セルなので最適化が埋める。
- **obstacle のクリアランスはボクセルに丸められる。** 1 ボクセル未満は切り上げて警告。
  mm 単位で効かせたいならグリッドを細かくする。

> **`volfrac` は自由セルにのみ掛かる。** 全体体積率 = preserve + volfrac ×（自由セル）。
> 結果は自由セル比と全体比の両方が出るので、現行設計と質量を揃えるならそこから逆算する。
>
> **形を決めているのが体積率ではなく強度であるべきときは `design.stress` を使う。**
> 既定は入っていない（`false` 相当。従来どおり体積率と剛性だけで形が決まる）。
> 使うときは、まず要求安全率（`safety_factor`）を決めてから回す——数値を大きくしすぎると
> 体積が `volfrac` から漂う。**体積が目標から離れて増えたら、その要求はその体積率では
> 実行不可能ということ。** エラーにはならないので、応力の行だけでなく体積の行も必ず読む
> （実測：SF 6 を要求すると volfrac 0.3 が 0.419 まで増え、それでも制約は破れたまま）。
> 詳細と拒否される組み合わせ（`--isotropic` との併用、OC 法との併用）は
> [spec.md](spec.md) §11.6。
>
> **`topopt compare` の `--origin` は設計空間モデルなら不要。** グリッド原点がサマリ JSON に
> 残るので自動で読む。旧方式（`topo_study.json`）の出力には原点が残っていないので `--origin` が必須。
> 原点は設計領域 STL の bbox 中心をグリッドに合わせた値：`origin = centre − shape × voxel / 2`。
> 自己比較（最適形状そのものを rebuild として渡す）でオーバーラップ 100%・コンプライアンス比 1.00 に
> なることは確認済み。おかしな数字が出たら原点を疑う。

## 8. 最適化結果は部品ではない — 必ず作り直す

最適化の生結果は**荷重経路の地図**であって部品ではない。取合い寸法がボクセルに量子化されており
（実測：1.607 mm ボクセルで 3.50 mm の溝が 3.21 mm、クリアランスが 0.50→0.21 mm）、
サポートも要る（実測：生結果 883 mm² に対し手作りの現行部品は 0 mm²）。
**2026-09-05 から生結果は既定で自己支持になった**（`design.overhang`、積層方向は `build_axis`、
プレートは設計空間の下端）。それでも残るサポートは preserve（取合い）の下面と、
45° ちょうどの面の丸め分で、頭部の下面などは CAD 側で面取りか尖り屋根にする。
`build_axis` は「解析した積層方向」であり「印刷する向き」でもあるので、`topopt print` の
向き探索でサポートを減らそうとせず、向きを変えたいなら study を変えて解き直す。

primitives で作り直し、**`topopt compare` で「作り直した形がまだ荷重を持つか」を証明する。**
最初の再構築は最適解より 5〜7 倍柔らかいのが普通で、その差は幾何的な重なり率には現れない。
手順と実測値は [../topopt/docs/topology-optimization.md](../topopt/docs/topology-optimization.md)。

## 9. 独立した再解析（CalculiX）

再構築した形が `topopt compare` の同条件 FEA を通ったら、仕上げに独立ソルバでも確認する。
`topopt fea` と同じボクセル・同じコードで検証しても系統誤差は相殺されて見えないので、
別のソルバ（CalculiX）・別のメッシュ（Gmsh の非構造四面体）で解き直す。

```bash
python -m topopt ccx part.stl --study study.json --out out/ccx --repair \
    --buckle --frequency --voxel-fea out/fea/<base>_fea.json
```

`--repair` は入力 STL が閉曲面になっていない（OpenSCAD 2021.01 系でよく起きる）ときに要る。
無指定で非閉曲面を渡すと終了コード 2 で止まる。`--buckle` / `--frequency` は座屈係数・
固有振動数を追加で解く（静解析とは別デッキになる。1つのデッキに混ぜると1ケースあたり
12ステップの `.frd` になり対応が取れないため）。`--voxel-fea` に `topopt fea` の出力
`*_fea.json` を渡すと、同じケースをボクセル経路とも突き合わせて `vs_voxel_fea_cases` に残す。

**既定の挙動を3つ知っておく。**

- **表面は既定で分割してから Gmsh に渡す。** Gmsh は渡された STL の三角形をそのまま
  境界メッシュにするので、分割しないまま `Mesh.CharacteristicLength` だけ細かくしても
  境界の解像度は変わらない（`lessons-learned.md` #73）。`--no-refine` で無効化できるが、
  **無効化した数値を「メッシュ収束スタディ」として引用しない**——境界の分解能を変えずに
  内部だけ細かくした数字は、収束していく系列になっていない。
- **境界条件は既定でボクセル経路と同じ体積マッピング（`--map volume`）。** 領域の内側に
  落ちる節点をそのつど拾う方式で、ボクセル FEA の拘束・荷重の定義と揃えてある。
  `--map surface` は表面節点だけを拾う代替経路。
- **荷重は既定で整合節点荷重（`--load-split consistent`）。** 二次要素（C3D10/TRI6）へ
  力を単純に等分すると角接点に余計に乗り、最悪要素の安全率が本来より低く出る
  （`--load-split equal` で旧方式に戻せる）。

読むところは4つ。

- **ケースごとの表**（`cases`）——最大変位・安全率（p99.5・最悪要素）・ホットスポット座標・
  反力モーメント・コンプライアンス・主応力/Tresca・座屈係数。荷重区分（`load_class:
  normal|abnormal`）ごとに要求安全率が変わる（通常は study の値、異常時は 1.5）。
  荷重ケースを1つの数字にまとめず、**全ケースを見る**。
- **釣合い誤差**（`equilibrium` / `moment_error`）——1% を超えていたら境界条件を疑う。
  拘束・荷重の持ち越し（`OP=NEW` の付け忘れ）はここで最初に壊れる。
- **メッシュ品質**（`mesh_quality`）——スライバー要素（q<0.02）が0.5%以上、または
  q<0.1 が5%以上あると `pass: false` になり、最大応力が「部品の値」ではなく
  「最悪要素の値」である疑いを警告する。
- **最悪要素ルール**——p99.5に対して最悪要素の安全率が1.5を下回るケースは合格にしない
  （spec §15.1）。`--exclude-mm D` で固定節点近傍だけをこの判定から除外できる（既定オフ、
  除外した内容は記録に残る）。

**ボクセル FEA との突き合わせ（`--voxel-fea`、`vs_voxel_fea_cases`）——2026-09-08 の続報。**
#A6 で食い違っていた原因はソルバではなくメッシュだった。粗い入力 STL（2048枚）は
「4/2/1 mm 収束スタディ」を回しても境界面が2048枚のまま変わっておらず、ある脚支持面は
STL 頂点9個だけしか掴んでいなかった。既定の表面分割（`refine_stl`）と体積マッピング
（`--map volume`）を揃えたところ、osmo_tripod・CalculiX 4 mm殻 vs ボクセル FEA 1 mm
（`fea --converge` の最細）の最大変位は**6ケース中6ケースが15%以内（最悪5.4%）**まで縮まった。
**ただし、これは「一致した」であって「収束した」ではない。** 同じ osmo_tripod を
`fea --converge` で4/2/1 mm回すと**全ケースが未収束**（p99.5応力が13〜32%動く）ので、
上の一致は今のメッシュ密度でのスナップショットにすぎない。一致しない食い違いを「誤差だから」で
無視しないのと同様、一致した食い違いも「決着した」と読み違えない——`docs/known-issues.md` A6 を読む。

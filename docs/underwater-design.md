# 水中部品の荷重・初期モデル・サポート

水中ドローンのブラケットやセンサーマウントを、新しいstudyとして作るための手順です。取合いと荷重の根拠を先に固定し、その間に材料を置ける空間を作り、探索後に完成形状を別ソルバとスライサーで確認します。密閉耐圧容器の設計認証やCFDは対象外です。

## 1. 荷重は部品の自由物体図から決める

部品だけを切り出し、接続先から受ける力とモーメント、作用点、支持する面を表にします。各値に「メーカー資料／実測／暫定上限」と単位を付けます。水深・流速・姿勢・搭載質量・排水体積・重心・浮心・推力・反トルク・テザーの張力が必要な入力です。知らない値を0に置かず、感度検討の幅として残します。

| 現象 | 設定方法 | 注意 |
|---|---|---|
| スラスター | 使用電圧・指令での前進／後進推力を別ケースにする | 停止推力と航走中の推力を混同しない。反トルクは推力からは決まらない |
| 搭載物の重さ | `W = m g`、浮力は `B = ρ g V` | 重心と浮心が違えば、差の力だけでなくモーメントも残る |
| 横流れ | `F = 0.5 ρ Cd A v²`。Aはその流れに垂直な投影面積 | Cdと基準面積の定義を合わせる。流速・Cdの幅で確認する |
| テザー・運搬 | 張力と作用点、実測または指定加速度でケース化 | 落下高さだけからピーク荷重は確定しない |
| 水圧 | `p = ρ g h`。密閉体は内外圧差を全外面へ | 小さな合力に潰し荷重を置き換えない。開放フレームにも局所圧力と浮力はある |

長さmm、力N、応力MPa、モーメントN mm。速度は`underwater-loads`に限りm/s。メーカーのkgfは9.80665倍でNにします。`loads[].force`は領域全体の合力で、節点ごとの値ではありません。

分布荷重を取合いへの等価荷重に置換するのは、**取り付けた機器から受ける荷重**です。部品自身への水圧・抗力を都合よく取合いへ移すと内部応力が変わります。現在のstudyはpreserveへの力と重力を扱い、`underwater-loads`の結果をFEA／最適化へ自動投入しません。密閉容器の外圧解析には別途分布圧力・座屈・内圧のモデルが必要です。

力の作用点が領域の重心からずれるなら、`M = r × F`を追加します。モーメントは距離dの二領域に±Fを置く偶力で表現し、`F = M/d`。グリッド上で実際に選ばれた節点の重心距離を確認し、合力と原点まわりモーメントが元の荷重と一致するか照合します。点荷重や点拘束を避け、実際の座面・接触範囲を使います。ボルトを全面固定する近似は締結接触や滑りを再現しません。

通常運転で同時に起きる推力・重量・横流れは同一ケースに合成し、排他的な最大値は別ケースにします。前後／左右／上下の反転や反トルク、故障・引っ掛かりの必要なケースを追加します。例の4ケースは入力形式の見本であり、実機の網羅的な荷重表ではありません。

根拠：[Blue Roboticsの推力・反転運転資料](https://bluerobotics.com/learn/thruster-usage-guide/)、[NASAの抗力式](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/drag-equation/)、[抗力係数と基準面積](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/drag-coefficient/)、[排水体積と浮力](https://www.grc.nasa.gov/WWW/K-12/WindTunnel/Activities/buoy_Archimedes)。確認日：2026-10-06。

## 2. 初期モデルは取合いと空間を分離する

1. 実測またはメーカーCADで座面・穴・締結工具の空間を確定する。取合いをpreserveとして残し、接続してよい面をattachで指定する。
2. design_spaceは取合いを結ぶ十分な包絡体にする。最初から細い完成部材を描くと、最適化が探せる荷重経路を先に潰す。
3. obstacleにプロペラ掃引域、ケーブル曲げ半径、コネクタ抜き差し、工具、排水口、サポートを取り出す開口を含める。
4. 箱・円柱などの解析的形状から始め、曲面の実機取合いはSTLで置換する。既存部品は比較対象またはoptional_starting_shapeに使い、固定して残す領域と混同しない。
5. setupで取合い消失・支持と荷重の重なり・attach・造形範囲を確認する。粗いグリッドで取合いが消えたら、荷重位置を動かして通さず解像度を上げる。

ボクセル幅は最小の荷重経路が複数要素で表される値から選び、setupの実測見積もりで費用を確認します。`filter_mm >= 3 × voxel_mm`は出発点で、最小部材寸法や収束の保証ではありません。細かい穴を仕上げるfinishは解析を精密化しないため、完成形状を再解析します。

材料と造形方向を固定して一案を探索し、比較は質量・最大変位・安全率・サポート量・時間・取合いを同じ条件で行います。どの形にも最良な初期形状やサポート方式はありません。応力が非活性ならstress制約を足すだけでは強度を決める形は変わらず、計算費だけ増えます。

## 3. サポートは設計時とスライス時の両方で扱う

最初は自己支持拘束を使います。取り外せる場所だけ許す場合は`design.overhang.allow_support`／`max_support_mm`を検討し、自己支持を全面OFFにする前に、向き・開口・分割を比較します。向きを変える場合は材料座標も変わるため再解析が必要です。

`topopt run ... --supports auto|none|tree --layer-mm 0.2`で完成STLを実スライスします。材料はstudyから引き継ぎます。比較時は同じSTL・向き・材料・層厚で、別の出力先へ`topopt slice`を実行してください。樹状が必ず軽い・速いとは限りません。生成された3mfの層プレビューで、座面・穴への接触と除去経路を確認します。

材料に適合するプレートも明示します。PETGの例は`--bed-type "Textured PEI Plate"`です。Bambuの既定プレートがCool Plateの場合、PETGを拒否することがあります。`slice`と`run`の両方で指定でき、指定値は`slice.json`に保存します。プレート選択のCLI仕様は[Bambu公式手順](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage)を参照してください。

`printcheck`は解析グリッドの垂直支持柱による概算です。樹状サポートの実形状や工具による除去性は判定しません。finishで形が変わった場合、その2項目を完成形状のPASSへ流用せずUNKNOWNにします。`slice.json`のサポート量はG-codeから集計した押出量で、部品空間の支持柱体積と比較しません。

## 4. 採用候補だけ仕上げる

`setup` → `run --quick` → 候補判定 → 同じ保存密度から`extract` → 完成STLの`ccx --converge` → スライス・レポートの順です。一括実行のCCXは完成形状を既定とし、別ソルバとの同形状比較には`--ccx-geometry analysis`を使います。完成STLの内容ハッシュと解析記録を照合します。

収束未確認、荷重未定、材料カード未実測、サポート除去性未確認を合格に置き換えません。濡れた材料、造形方向、締結状態を合わせた試験片と実部品の静荷重試験が最終的に必要です。ソフトウェアの回帰試験に通ったことと、実部品の実証は別です。

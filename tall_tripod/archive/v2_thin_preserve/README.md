# v2 — the run whose supports were two elements thick

**証拠として残しています。結果としてではありません。** tall_tripod の2番目の run
（2026-08-05、コミット `0f2f732`、4.0 mm ボクセル・40 反復・81 分）。

v1 と違って**印刷できる形**が出ました（212 × 184 × 144 mm、Z を上にしてベッドに載る）。
判定は FAIL 3 / UNKNOWN 2 / PASS 9。差し替えたのは、その FAIL のうち1つの
**原因を測って、モデル側の欠陥だと分かった**からです。

> 接地パッドとハブ座の厚みが 9.0 mm で、4 mm グリッドでちょうど**2ボクセル**だった。
> 「最も薄い断面に 3 要素以上」の判定はここで落ちていた。
> そして応力の最大点は z = 2 mm と z = 10 mm ——**まさにそのパッドの中とすぐ上**。
> つまり**支持部まわりの応力値が、この解像度では信用できなかった**。

最適化は何も悪くありません。**フィルタは効いていました**——最適化された材料は
2ボクセルの断面をひとつも作っていません（下の表）。落としていたのは、
最適化が触れない CAD 側の寸法でした。

## 判定を落としていたのがどこか（この run の実測）

部品全体の断面厚（距離変換の尾根）443 点の内訳：

| | 尾根の点 | うち 2 ボクセル以下 |
|---|---|---|
| preserve（9 mm のパッド・ハブ座・頭部） | 180 | **169** |
| 最適化された材料 | 263 | **0**（p5 13.86 mm） |

この測定が `docs/known-issues.md` G1 と `docs/lessons-learned.md` #49 の根拠です。
**当初は「Heaviside 射影が境界を尖らせるせい」と書いていました。測って否定されました。**

## 何を変えたか

`tall_tripod.scad` の `z_leg_tip` を **9.0 → 13.0 mm**（3ボクセル）。
設計空間（高さ 22 mm の円板）は**変えていない**ので、最適化が使える空間は同一です。
preserve だけが 50,496 → 65,664 mm³ に増えます。

**16 mm 以上にはしませんでした。** 薄い点は減らず（25 → 27 と増える）、
ハブ座が太って**母数を薄めるだけ**で判定を「通し」ます。それは直したことになりません。

## これでも消えない FAIL

- **メッシュ判定は通りません。** 残る 19 点はマウント頭部＝**カメラ取合い**で、
  相手の寸法が決めているので厚くできません。推定 5.9 %（合格には 5 % 未満が必要）
- **取合い面へのサポート着地（1,568 mm²）**は解像度と無関係です

つまりこの変更が買うのは判定ではなく、**支持部の応力が信用できるようになること**です。
